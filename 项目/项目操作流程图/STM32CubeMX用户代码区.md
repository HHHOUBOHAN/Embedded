

下面我抛开长篇大论，给你一份 **“STM32CubeMX用户代码区”纯干货速查教程**。记住核心铁律：**所有代码必须写在 `BEGIN` 和 `END` 中间，外面写了必丢！**

---

### 🗺️ 全区块“一句话”定位地图（按执行顺序）

#### 1. `USER CODE BEGIN Includes` —— **头文件引专区**
- **写什么**：`#include "xxx.h"`（你自己写的驱动头文件，比如液晶屏、传感器、WiFi模块）。
- **不写什么**：变量、函数、执行语句。
- **示例**：`#include "oled.h"` / `#include "bsp_uart.h"`

---

#### 2. `USER CODE BEGIN PV` —— **全局变量仓库（永久存储）**
- **写什么**：全局变量、数组、结构体、宏定义（`#define`）、类型重定义（`typedef`）。
- **不写什么**：`HAL_GPIO_WritePin(...)` 这种运行的代码；也不要写在 `main()` 里面，否则会变成局部变量，循环一次就丢数据。
- **示例**：`uint8_t rx_buffer[100];` / `#define LED_ON HAL_GPIO_WritePin(...)`（宏可以放这里）

---

#### 3. `USER CODE BEGIN PFP` —— **函数声明区（先打招呼）**
- **写什么**：你自己写的函数的**声明**（只有函数头，没大括号内容），防止编译器报警告。
- **不写什么**：函数的具体代码实体（大括号里的东西）。
- **示例**：`void UART_SendData(uint8_t *data);`

---

#### 4. `USER CODE BEGIN 0` —— **函数实体加工厂（最常用）**
- **写什么**：你自己所有自定义函数的**具体实现代码**（带大括号的实体）。比如延时函数、计算函数、硬件驱动函数。
- **不写什么**：不要写 `main` 循环里的业务逻辑，只写工具函数。
- **示例**：`void LED_Blink(void) { HAL_GPIO_TogglePin(...); }`

---

#### 5. `USER CODE BEGIN 1` —— **“裸奔”预操作区（极度危险，少用）**
- **写什么**：读取芯片唯一ID（UID）、操作备份寄存器、底层复位标志。**完全不依赖时钟的底层硬件操作**。
- **不写什么**：**严禁**写 `HAL_Delay`、串口发送、ADC读取等任何外设API，因为此时系统时钟还没配置，调了直接死机。
- **示例**：`uint32_t uid = HAL_GetUIDw0();`

---

#### 6. `USER CODE BEGIN 2` —— **上电一次初始化区（最常用）**
- **写什么**：所有**只在上电执行一次**的业务。比如：屏幕清屏、打印开机日志、开启中断接收（`HAL_UART_Receive_IT`）、设置引脚初始高低电平。
- **不写什么**：不要写需要反复执行的按键扫描、数据轮询。
- **示例**：`OLED_Init();` / `printf("System Ready!\r\n");`

---

#### 7. `USER CODE BEGIN WHILE` —— **主循环干活区（核心业务）**
- **写什么**：需要**无限重复执行**的主要逻辑。比如：按键扫描、ADC连续采样、串口数据解析、状态机运行。
- **不写什么**：延时函数（`HAL_Delay`）最好挪到下面的 3 号区，除非你有特殊时序要求。
- **示例**：`Key_Scan();` / `Parse_Command();`

---

#### 8. `USER CODE BEGIN 3` —— **循环收尾打扫区**
- **写什么**：每轮 `while(1)` 循环**最后**干的事。比如：统一给一个短延时（控制循环速度）、喂独立看门狗（`IWDG`）、进入低功耗休眠。
- **不写什么**：不要在这里写复杂运算，它就是循环尾巴。
- **示例**：`HAL_IWDG_Refresh(&hiwdg);` / `HAL_Delay(10);`

---

#### 9. `中断服务函数内的 0 和 1`（在 stm32xx_it.c 里）
- **0区（前置区）**：在 HAL 库处理中断**之前**执行，极少用，除非你要抢救临界寄存器。
- **1区（后置区，重点）**：在 HAL 库处理完中断**之后**执行。**99%的中断业务写在这里**。比如串口收到数据后，在这里把数据拷贝出来，置位接收标志。
- **示例（串口中断 1 区）**：
  ```c
  if(huart1.RxState == HAL_UART_STATE_READY) {
      rx_flag = 1; // 告诉主循环有数据来了
  }
  ```

---

#### 10. `HAL库弱回调函数内部`（文件最底部）
- **写什么**：中断事件触发后的**具体反应**。比如 `HAL_UART_RxCpltCallback`（接收完成回调）里，把收到的字节存进数组。
- **示例**：`buffer[index++] = huart->Instance->DR;`

---

#### 🚫 终极避坑三板斧（背下来）
1. **变量放 PV，函数放 0，初始化放 2，循环放 WHILE**——顺序记错，程序必崩。
2. **BEGIN 1 是禁区**，除了读UID，尽量空着别动，动了容易进硬件错误。
3. **千万别在 `BEGIN/END` 外面手贱加任何代码**，哪怕加一行 `//` 注释，重新生成CubeMX后全部灰飞烟灭。

如果觉得上面太散，**死记这个顺口溜**：
> *头文件放 Includes，全局变量属 PV；*
> *函数声明扔 PFP，函数实体归 0 区；*
> *1 区别碰时钟起，2 区只跑一次戏；*
> *While 区干重活，3 区喂狗别犹豫！*
