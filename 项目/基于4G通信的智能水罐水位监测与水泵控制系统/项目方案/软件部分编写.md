# 软件架构的选择
## 三种方案的对比

| 方案             | 结构                 | 优点           | 缺点               | 适合情况     |
| -------------- | ------------------ | ------------ | ---------------- | -------- |
| 裸机轮询           | `while(1)` 顺序执行    | 最简单          | 一旦某个函数阻塞，全部卡住    | 小练习、闪灯   |
| 裸机 + 状态机       | `while(1)` 调度多个状态机 | 稳定、好调试、资源占用小 | 需要主动设计非阻塞逻辑      | 你的第一版    |
| FreeRTOS + 状态机 | 多个任务并发运行           | 模块隔离强，后期扩展好  | 调试复杂，需处理队列、互斥锁、栈 | 多任务、复杂项目 |
本项目的第一版使用`裸机 + 状态机` 方案，后序第二版会改为 `FreeRTOS + 状态机`
**第一版：超级循环负责调度，状态机负责逻辑。**  
**后续升级：FreeRTOS 负责调度，状态机仍负责逻辑。**

# 1. STM32 BSP 层代码编写
## 1.1 BSP层
- 业务逻辑与 STM32 HAL/真实硬件之间的适配层。它把 GPIO 高低电平、有效电平、端口和引脚等硬件细节封装起来给
- 给上层提供清晰接口，给上层一个接口
## 1.2 硬件准备
### 1.2.1 硬件资源表

|        |             |        |           |        |              |
| ------ | ----------- | ------ | --------- | ------ | ------------ |
| 硬件     | CubeMX 标签建议 | 方向     | 有效电平      | 上电安全状态 | 备注           |
| 运行 LED | LED_RUN     | 输出     | 根据电路确定    | 灭      | 可能低电平点亮      |
| 报警 LED | LED_ALARM   | 输出     | 根据电路确定    | 灭      | 与运行灯分开       |
| 蜂鸣器    | BUZZER      | 输出/PWM | 根据模块确定    | 关闭     | 确认有源还是无源     |
| 水泵继电器  | RELAY_PUMP  | 输出     | 根据模块确定    | 必须关闭   | 高压负载先不要接     |
| 功能按键   | KEY_1       | 输入     | 按下为 0 或 1 | 稳定未按下  | 常见为上拉输入、按下接地 |
| 模式按键   | KEY_2       | 输入     | 按下为 0 或 1 | 稳定未按下  | 需要消抖/长按      |

### 1.2.2CubeMX 配置
1. 将所有 LED、蜂鸣器、继电器配置为 GPIO_Output；按键配置为 GPIO_Input。
2. 为每个 GPIO 设置 User Label，确保 main.h 自动生成清晰的 *_Pin 和 *_GPIO_Port 宏。
3. 为按键选择正确的 Pull-up / Pull-down；不要同时依赖外部上拉和错误的内部下拉。
4. 输出引脚的初始电平必须保证“**继电器关闭、蜂鸣器关闭、LED 状态可控**”。
5. 生成代码后确认 MX_GPIO_Init() 中的初始 HAL_GPIO_WritePin() 与 GPIO_InitStruct 配置正确。
6. 先编译一次 CubeMX 原始工程，保证 0 Error，再开始写 BSP。
### 1.2.3 统一有效电平
- 很多模块是“低电平有效”。如果直接在业务代码里写 GPIO_PIN_SET/RESET，很快会混乱。建议在 BSP 内部统一转换，上层只使用 ON/OFF。
- 设置公共状态类型
```
typedef enum
{
BSP_STATE_OFF = 0;
BSP_STATE_ON = 1
}BSP_State_t;
```
## 1.3 代码编写
### 1.3.1 LED
####  硬件
**认识电路**
1. 电路
```
3.3V → 电阻 → LED → GND
```
2. 电压差产生电流，有电流`LED`亮
3. 输出低电平的时候，没有电压差，输出高电平，有电压差
**引脚配置**
- 输出（输入：外面的硬件把信号送给 STM32，比如按键 输出：STM32把信号送给外面的硬件 比如`LED`）
- 引脚：`RUN_LED → PB14`,  `FAULT_LED → PB15`
- 有效电平：对于这个`LED`, 能把这个灯点亮就是就是有效电位，故这个是高点平有效

| GPIO状态           |  引脚电压 | LED状态 |
| ---------------- | ----: | ----- |
| `GPIO_PIN_RESET` |   约0V | 灭     |
| `GPIO_PIN_SET`   | 约3.3V | 亮     |
|                  |       |       |
- 上电时候处于啥状态：两个灯初始输出电平都是低电平，故上电默认灭
- GPIO配置模式：
	- 工作模式：`GPIO Output`，
	- 输出电路类型：`Output Push-Pull` 推挽输出 (主动输出高电平，低电平)，No Pull（这个只用于这个输入引脚）
	- `No Pull` ：没有内部上下拉， 不接内部上拉或下拉电阻
	- 初始化输出状态：初始 Low
	- 边沿切换速度：GPIO电平从0V变到3.3V，或者从3.3V变到0V时的边沿速度和驱动能力设置 `Low Speed`
#### 软件
**接口**
1. 初始化： `LED_Init()`
2. 亮:`LED_On(uint8_t led)`
3. 灭: `LED_Off(uint8_t led)`
4. 翻转状态:`LED_Toggle(uint8_t led)`
5. 获取状态:`LED_GetState(uint8_t led, uint8_t *state)`
6. 设置状态:`LED_SetState(uint8_t led, uint8_t state)`
### 1.3.2 buzzer
####  硬件
**认识电路**
1. 电路![[Pasted image 20260803130800.png]]
```
+5V_SYS
   ↓
BUZZER1 有源蜂鸣器
   ↓
Q2 AO3400A NMOS
   ↓
GND
```
2. STM32 的控制路径则
```
STM32 PB13
 ↓ 
BUZZER_CTRL
 ↓ 
R14 100Ω
 ↓ 
Q2 栅极 Gate
```
3. STM32不直接给蜂鸣器供电 STM32只控制MOS管开关 MOS管负责接通或断开蜂鸣器的5V电流
	- 因为STM32GPIO 通常是 3.3V 逻辑，无法输出5V
	- 蜂鸣器需要的电流可能高于 GPIO 适合长期提供的电流
	- 如果蜂鸣器内部包含线圈，断电时可能产生反向电压，对 MCU 引脚不友好
4. [MOS管](https://www.bilibili.com/video/BV1344y167qm?t=280.9)
	- STM32只提供很小的栅极控制电流   MOS管承担蜂鸣器工作电流  这种模式叫做低端开关驱动
	- Q2 AO3400A   Q2 是一个 N 沟道 MOSFET![[Pasted image 20260803124538.png]]
	- 三个重要引脚：G：Gate，栅极         D：Drain，漏极              S：Source，源极
	- 本项目的引脚连接`Gate ← BUZZER_CTRL` ,  `Drain ← 蜂鸣器负端`,`Source → GND`
	- 工作原理： 当栅极没有电压的时候，漏和源之间是截至的，当给这个栅极施加电压，漏和源之间导通 ![[Pasted image 20260803124734.png]]
	- 半导体结构：当接上这个电源的时候形成了两个半导体，一个导通，一个截至，为了让他导通通过在p区加上栅极（二氧化硅绝缘层和这个金属板），当给栅极接电，可以将P区中的电子吸引到这个绝缘层附近，从而把空穴赶走，电压越大，吸引的电子就越多，当电子吸引的足够多的时候，从而形成N沟道![[Pasted image 20260803125043.png]]
	- 特性：
		- mos的栅极的输入阻抗非常高，栅极中有这个绝缘层的存在，几乎无法与这个P极的电子相结合
		- 栅极容易被静电击穿：栅极输入阻抗很大，感应电荷很难释放，产生的高压很容易把这个薄绝缘层击穿，造成mos管永久损坏
5. 工作原理：
	- BUZZER_CTRL 输出高电平 `PB13输出高电平 → Q2栅极电压升高 → Q2导通`  主电路形成完整回路，蜂鸣器得到供电并发声
	- BUZZER_CTRL 输出低电平 `PB13输出低电平 → Q2栅极接近0V → Q2关断`   回路断开， 蜂鸣器无供电不发声
6. R14 的 100Ω
```
STM32 GPIO → R14 100Ω → MOS管Gate
```
- MOS 管栅极虽然正常工作时几乎不持续耗电，但栅极内部存在电容。电平切换瞬间，相当于要给这个小电容充电或放电，可能出现瞬时电流。
- R14 的作用主要有：
```
限制栅极瞬时充放电电流
减小GPIO瞬间冲击
抑制高频振铃
降低电磁干扰
保护STM32和MOS管栅极
```

- 同时电阻不能太大：否则栅极充电太慢→MOS管开关过程变慢→MOS管可能在半导通区停留更久
7. R15 的 10kΩ(栅极下拉电阻)
```
Gate
 ↓ 
R15 10kΩ
 ↓ 
GND
```
- 作用：STM32刚上电或复位时，GPIO可能暂时处于高阻输入状态。这时 MOS 管栅极如果没有 R15，就可能处于悬空状态
- 如果有 外接干扰 静电 栅极残留电荷  Q2 都能意外导通 可能会出现 刚一上电，蜂鸣器突然响一下
- 当有了这个R15 会把 Gate 稳定拉到 0V：`STM32还没初始化→ R15把Gate拉低→ Q2保持关断→ 蜂鸣器默认不响
- 为啥选择`10kΩ`z ： 
	- 这个下拉电阻主要的作用:
		- STM32没有输出的时,拉低Gate
		- STM32输出高电平时,不能消耗太大电流
		- 当GPIO输出 3.3V时， 流经10kΩ 的电流大约只有`3.3V ÷ 10000Ω ≈ 0.33mA` 对GPIO负担很小
8. D3 SS14
- 作用：D3 跨接在蜂鸣器两端附近，是一个保护二极管，标准作用是`续流 钳位反向电压 保护MOS管`
- 如果蜂鸣器内部存在电磁线圈，工作时线圈会储存磁场能量，当 Q2 突然关闭时，线圈电流不能瞬间变成 0，会试图产生很高的反向电压
```
Q2突然关断 → 线圈继续维持电流 → 漏极电压瞬间升高 → 可能击穿MOS管
```
- 为了避免击穿MOS管：通过这个D3形成一个安全回路`蜂鸣器线圈 → D3 → 蜂鸣器线圈` ，让能量慢慢释放，而不是形成高压尖峰
8. 蜂鸣器
- 蜂鸣器具有极性：
	- 连接关系：`蜂鸣器正极 → +5V_SYS`        `蜂鸣器负极 → Q2漏极` 不能反接
**引脚配置**
- 输出
- 引脚：PB13
- 有效电平：高电平有效
- 上电状态： 默认关闭，不响，cubeMX配置和这个驱动初始化双重保险
- Push Pull 推挽模式
- 外部已经有R15 10kΩ下拉，不需要配置下拉`No Pull`
#### 软件
1. 为了实现这个驱动的移植 可以让蜂鸣器驱动已经和具体引脚解耦 逻辑如下:
```
CubeMX生成的实际引脚
        ↓
    board.h 板级映射
        ↓
buzzer.c 驱动逻辑
        ↓
应用层  
```
- 通过这个实现这个**驱动独立**，从而实现以后驱动的复用

```

```

**按键功能**
1. **自动**/**手动模式切换**
	 - **自动模式**：系统根据水位自动控制
		- 水位低于启动下限并持续一定时间（这个时间不能本地和联网控制 直接软件写死）→ 自动启动补水
		- 水位达到停止上限 → 自动停止补水
	 - **手动模式**: 用户通过按键请求启动或停止
		- 用户通过按键请求启动或停止
		- 手动不能越过这个：
			- 过压保护
			- 高水位保护
			- 传感器异常
			- 故障锁定
			- 最大运行时间保护
2. **启动功能**：
	- 手动模式: 得到这个启动命令之后，经过安全判断后，才允许继电器开启
	- 自动模式：自动模式没有启动水泵功能的说法，但是要考虑这个手动模式到自动模式切换的时候的情况，就是恢复这个自动控制的时候，这里不是强行打开水泵，而是取消“自动暂停”。恢复以后，系统重新根据水位判断是否需要启动。
3. **停止功能**：停止是最高优先级的任务
	- 手动模式：按下停止 → 立即关闭继电器
	- 自动模式：切换到这个自动控制模式，显示这个`AUTO_PAUSED 自动暂停`, 否则下一次检测到检测到低水位，还是会重新启动
4. **蜂鸣器消音**：
	- 实现功能: 报警消音和这个解除消音
	- 消音 ≠ 清除报警  
		- 水泵仍然停止
		- 故障灯仍然亮
		- OLED 仍然显示过压
		- MQTT 仍然上报过压
		- 只关闭蜂鸣器声音

5. **参数设置操做功能**
- 进入设置页面:  进入设置菜单时继续正常控制；编辑中的参数暂不生效，确认保存后一次性生效。
- 选择参数：

	- 最大运行时间（这个不用 现在是小灯泡项目 不需要的）
- 参数增加和减少：
	- 可选参数：水位上下限，压力上下限，

**其他元器件作用**
1. `R8`的`100Ω`
- MOS管栅极正常稳定时几乎没有持续电流，但栅极存在等效电容
- GPIO从低电平切换到高电平时，相当于给栅极电容快速充电；从高电平变低时，相当于快速放电
- R8主要作用：
```
限制栅极瞬时充放电电流
减小STM32 GPIO瞬时冲击 
抑制高频振铃 
降低电磁干扰 
改善MOS管开关边沿
```
- 为啥选`100Ω`：电阻越大，Gate 充放电越慢，MOS 管开关速度越慢。 而这个继电器不像这个`pwm`那样有这么高的要求
2. `R9`的`10kΩ`
- 栅极下拉电阻
- 设备刚上电或STM32复位时，PB12可能暂时处于高阻状态。
- 如果没有`R9`
```
Q1 Gate悬空
→ 栅极可能保留电荷
→ 受到电磁干扰
→ Q1可能意外导通
→ 继电器突然吸合
→ 水泵可能意外启动
```
 - 有了`R9`
```
STM32尚未初始化
→ R9把Gate拉到0V
→ Q1保持关断
→ 继电器保持释放
→ 水泵默认停止
```

当PB12输出3.3V时，流过R9的电流很小，对STM32负担不大，所以R9是这个继电器电路中的重要安全元

```
I = 3.3V ÷ 10000Ω
I ≈ 0.33mA
```
3. `D1 SS14`的作用
- D1跨接在：继电器线圈两端 他是继电器线圈的 续流二极管
- 正常通电
```
+5V_SYS给线圈供电 → D1反向截止 → D1不参与正常工作
```
- Q1突然关断时
```
线圈电流不能瞬间变为0
 ↓
线圈试图产生反向高压
 ↓
D1导通
 ↓
线圈电流通过D1形成续流回路
 ↓
磁场能量逐渐释放
```
作用：
```
钳位Q1漏极电压 保护AO3400A 减少电磁干扰 降低继电器释放时对5V和MCU的冲击
```
3. `D2 1N4007`
- 并联在外部24V接触器线圈两端
- 作用：
 ```
 接触器线圈突然断电
 ↓
线圈产生反向感应电压
 ↓
D2导通
 ↓
提供续流通路
 ↓
保护RLY1触点
 ↓
减少触点拉弧和电磁干扰

1N4007本身属于通用整流二极管，也可以用于普通低频感性负载续流
 ```
