## 底层驱动编写流程

### 1. 先学习硬件

先确认：

- 芯片或模块是做什么的；
    
- 原理图电路如何连接；
    
- 每个引脚有什么作用；
    
- 有效电平是什么；
    
- 上电默认状态是什么；
    
- 是否有分压、上拉、下拉或保护电路；
    
- 芯片的通信时序；
    
- 电压是否匹配；
    
- 异常和断线时引脚会是什么状态。
    

### 2. 再确认CubeMX配置

检查：

- GPIO输入还是输出；
    
- 推挽还是开漏；
    
- 是否需要上下拉；
    
- 默认输出电平；
    
- GPIO速度；
    
- 外部中断；
    
- 定时器频率；
    
- 中断优先级；
    
- CubeMX生成的真实标签。
    

### 3. 再设计软件接口

先写清楚驱动应该对外提供什么，例如：

```c
void XXX_Init(void);
void XXX_Update(uint32_t now_ms);
bool XXX_GetData(...);
bool XXX_IsValid(void);
```

同时确定：

- 哪些函数由主循环调用；
    
- 哪些函数由中断调用；
    
- 哪些变量需要 `volatile`；
    
- 是否使用状态机；
    
- 如何判断超时；
    
- 如何防止阻塞主循环。
    

### 4. 最后编写代码

顺序固定为：

```text
board.h硬件映射
        ↓
驱动头文件xxx.h
        ↓
驱动源文件xxx.c
        ↓
main.c初始化和调度
        ↓
中断回调
        ↓
单模块测试
```
 

```
第一步：认识硬件和工作原理
第二步：阅读原理图
第三步：确认引脚和电平
第四步：确认CubeMX配置
第五步：设计驱动接口
第六步：编写board.h映射
第七步：编写.h
第八步：编写.c
第九步：接入main.c和中断
第十步：编译并解决报错
第十一步：单独测试硬件
第十二步：确认稳定后再写下一个模块
```
