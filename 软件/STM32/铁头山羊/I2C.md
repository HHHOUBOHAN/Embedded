# 1.1 基本电路结构
## 1.1.1 串口的缺点
1. 传输速度相对慢
	- 串口是一位一位传的，相比并口、USB、以太网这种高速通信，速度比较低
	- 常见波特率为：`9600  115200  921600`虽然能用，但传大量数据时比较慢
2. **一次只能点对点通信**
	- 普通UART一般是两个设备之间通信
		- 设备A_TX ---- 设备B_RX
		- 设备A_RX ---- 设备B_TX
		- GND     ---- GND
	- 如果多个设备同时挂一条线上，就容易冲突,不像 I2C 那样天然支持多个从机地址
3. 没有地址机制
	- 串口本身只负责收发数据，不知道：这个数据发给谁 ，这个数据从谁来
	- 如果多个设备通信，需要自己设计协议: 帧头 + 设备地址 + 数据 + 校验 + 帧尾
4. 发送和接收双方波特率必须一致
	-  如果STM32设置和串口设置不同就会出现：乱码  收不到数据  数据错误
5. 抗干扰能力一般
	- 普通 TTL 串口电平是：`0V / 3.3V`
	- 距离远了容易受干扰,所以普通 UART 适合短距离通信
	- 如果距离远，转成 RS232  RS485  CAN
6. 没有时钟线，依赖双方时钟精度
	- UART 是异步通信，没有专门的时钟线。
	- 双方靠约定好的波特率来同步。
	- 如果时钟误差太大，就可能采样错误，导致乱码。
## 1.1.2 I2C的电路结构
1. 电路图                                                                                                                                                                  ![[Pasted image 20260705211703.png]]
2. 两个数据线：串行时钟线  串行数据线  
3. 主机  从机（每一个从机都有一个SCL SDA）
4. SCL SDA都有上拉电阻
5. 从机都有一个7位的地址  从`0000000`到`1111111` ,可以理解为0到127，故总共又128个地址 ，最多可以和128个从机通信
6. 通信流程：主机发送从机1地址，与从机1建立通信，当与从机1通信完成后，主机会和其他从机建立连接，以此类推
## 1.1.3 数据线和时钟线
1. 时钟线传输时钟，数据线传输数据
2. **时钟信号总是从主机发送给从机**，数据信号通信方向是**双向**的
3. 时钟信号每一个周期，数据信号会传输一个数据，所以时钟信号的频率（周期）决定了数据传输的快慢
## 1.1.4 逻辑线与
1. SCL和SDA都有一个上拉电阻
2. 从机和主机的所有的SCL和SDA引脚都设置为开漏输出（单片机通过驱动一个MOS管来驱动IO引脚的输出高低电压的，开漏模式即上面MOS管断开，只控制下面的MOS管，写0的时候下面MOS闭合，输出的是低电压，写1的时候下面的MOS管断开，输出的是高阻抗）
3. 通过上述的上拉电阻和开漏输出从而实现逻辑与运算（只要任何一个数等于0，其结果就为0）
	- 模拟一下多个设备连接在同一根线上的场景（线上有上拉电阻，且所有挂载设备都是开漏输出）
	- SDA和SCL这两根线，各自有一个上拉电阻，默认为高电平
	- 这样设计就形成了**有0为0，全1为1**
	- 主机（谁产生时钟信号（SCL），谁就是主机；被时钟信号驱动的，就是从机，即谁发数据，谁就是主机）
	- 从机（接收产生的时钟信号，进行地址比对，然后发出(ACK)或数据）
	- 硬件回读：**发出一个动作 + 立刻测当前的总线电压 + 与自己在内部比对一下。** 
		-  发和读结果相同：继续保持“发送”状态，准备下一个bit
		-  发和读结果不同：立刻强制关闭当前设备SDA引脚的输出驱动器（变成高阻态，不再输出任何电平），设备状态从“主机发送模式”切换为“从机接收模式”
	- 设计好处：
		- **多主机仲裁（抢总线）**（数据线SDA）：
			- 按位（bit）进行的，也就是每一个“时钟周期”（SCL高电平期间）进行一次判断，一个周期对应的是传输 **1个 bit**，八个周期等于一个字节
			- 过程：
				-  总线上有两个主机A和B,同一时刻开始发送数据
				- A: 1 0 1 1 0 1 0 1
				- B: 1 0 1 1 1 0 0 0
				- 第一个时钟周期：主机A和主机都想发1，没有人拉低SDA,上拉电阻把SDA拉到了高电平，总线状态=1，然后进行硬件回读判断SDA状态
				- 第二个时钟周期：主机A和主机B都发0，拉低了SDA,硬件回读判断一致，继续
				- 第三个时钟周期和第四个时钟周期，与第一个时钟周期相同
				- **第五个时钟周期**：发生冲突
					- **主机 A 想发**：`0`   动作：**拉低 SDA（管子导通，强行接地）**
					- **主机 B 想发**： `1`  动作：**释放 SDA（管子断开，不管）**
					- 结果：主机A拼命拉低，B只是放手，所以线与的结果就是`0`,这个就验证了**有0为0，全1为1**
					- 硬件回读：主机A读回SDA引脚，看到总线是0，两者相同，继续发送，主机B读回SDA引脚，看到的是0，但是发送的是1，发送和读回不同，说明有人在拉低
					- 主机B动作：立即关闭SDA驱动，把自己的状态从“发送”切换为“接收”
				- 第6，7，8个周期
					-  主机A：继续按照自己的节奏，发送1，0，1
					-  主机B: 一直保持接收
				- 为啥B转换为接收后，下一个周期就不能发送了：两个主机向同一个从机发送数据时，如果B下一个周期还是能发送，后序可能一个字节的数据既包括A的又包括B的，导致数据污染
		- **时钟拉伸（逼停）**（时钟线SCL）
			- I2C 是同步通信，主机负责发时钟（SCL 高高低低），从机跟着节奏走，但是当主机速度太快，从机反应不过来，就需要让从机拥有一个能力，即时钟拉伸（逼停）
			- 原理：
				- **正常情况（开漏+上拉）**：SCL 和 SDA 一样，都是开漏输出。主机只能“主动往下拉（0）”或“被动松手放高（1）”。正常时，主机拉低半个周期，松手半个周期。
				- **拉伸原理**：因为总线上允许“线与”，从机拥有和主机一样强制的“下拉权”。**只要从机不松手（强行输出0），哪怕主机松手了，SCL 也绝对升不上去。** 主机一旦回读发现 SCL 还是 0，就会被迫暂停时钟。
			- 流程：
				- 一个标准的时钟周期 = **1 个低电平半周期 + 1 个高电平半周期**
				- 第一个半周期（低电平）准备期：这半个周期的任务是主机把线拉低，准备数据
					- 主机内部：定时器说“开始”，主机打开内部的下拉MOS管（接地），SCL 变成0。同时主机把要发送的0或1放到SDA 数据线上。
					- 从机暗中操作：从机如果发现自己数据没处理完（反应不过来），就在这个低电平期间，悄悄打开自己的下拉MOS 管
					- 物理总线：主机拉低，从机也拉低。SCL 稳稳保持在 OV，此时大家相安无事。
				-  第二个半周期（高电平）发送期：
					- **主机想松手**：主机**关闭自己的下拉 MOS 管（松手）**，想让上拉电阻把 SCL 拉高
					- **从机死拽（拉伸发生）**：因为从机死死按住，SCL 依然保持 **0V**
					- **主机回读（发现被坑）**：主机的回读器回读是有人拽着，从机在进行时钟拉伸，于是**主机的内部定时器直接挂起（暂停计时），程序死等**
					- **从机松手（解除警报）**：从机处理完数据，关闭自己的下拉 MOS 管（松手）。上拉电阻终于发力，把 SCL 拉到了真正的 **高电平（1）**
					- **继续通信**：主机回读看到 1，定时器恢复计时，这一个“被无限拉长的高电平半周期”才真正开始并结束。从机趁着此时的高电平读取 SDA。
					- 时钟拉伸的本质就是：从机利用硬件的“线与”，在主机想给高电平时“强行踩刹车”，把主机框在“低电平等待”的状态里，直到自己准备好才允许时钟继续走。
		- I2C传输数据原理：
			- 一个标准的时钟周期 = **1 个低电平半周期 + 1 个高电平半周期**
			- 第一个半周期（SCL低电平）准备期：
				- 主机准备发1：因为是开漏输出，所以主机断开自己内部下拉MOS管，上拉电阻悄悄把SDA拉高到高电平（3.3V）
				- 主机准备发0：主机闭合自己的内部的下拉MOS管（导通），SDA线被强行拽到地（0V）
				- 从机动作：从机看到SCL是低电平,主机要有一段时间去稳定电平，不会去读SDA数据
			- 第二个半周期（SCL高电平）发送期：
				- 主机输出0，SCL被上拉电阻拉高到1
				- 此时，SDA线上已经稳定刚刚低电平的状态（不是被主机拉着，就是被上拉电阻拉着）
				- 从机的回读器工作，去读取SDA电压

## 1.1.5 主机如何发送时钟信号
1. 主机通过内部硬件定时器（或软件控制GPIO引脚翻转），在时钟线（如SCL/SCK）上持续输出高低电平交替的方波，充当整个总线通信的“节拍器”，从而规定数据位的传输节奏（通常是低电平改数据、高电平读数据）；虽然I2C等协议允许从机通过“时钟拉伸”短暂强按住时钟线让主机等待，但时钟信号的产生和总体控制权绝对属于主机
## 1.1.6 主机如何发送数据
1. 从机SDA引脚写1，控制主机的SDA向引脚上写0或1，写0低电压，写1高电压
## 1.1.7 从机如何发送数据
1. I2C数据通信是双向的，主机向SDA引脚写1，释放SDA线，除通信的从机外，其他引脚都写1，通信从机写0和1给主机发送信息
