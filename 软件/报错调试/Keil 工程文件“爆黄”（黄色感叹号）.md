# 📝 Keil 工程文件“爆黄”（黄色感叹号）及找不到头文件报错排查指南

## 一、现象描述

1. 工程左侧项目树（Project Tree）中的`.c`或`.h`文件图标上出现**感叹号**。
    
2. 点击编译（Build/Rebuild）后，下方输出窗口出现大量红错： `Error: #5: cannot open source input file "xxx.h": No such file or directory`。
    
3. 甚至连编译器自带的标准库文件（如`stdint.h`，`stddef.h`）都会报错找不到。
    

## 二、核心原因分析

“爆黄”不是因为代码写错了，也不是因为编译器版本选错了，**100%是因为开发环境的“路径”断了或乱了**。具体原因有清楚：

1. **缓存作祟（最常见）：** Keil的用户选项缓存文件（`.uvoptx`）记住了原作者电脑上的旧绝对路径（或者你之前错误配置的路径），导致编译器变成了“眼睛瞎了”。
    
2. **Include Paths 配置错误：**头文件（`.h`）所在的文件夹，没有被添加到 Keil 的“包含路径”列表中。
    
3. **文件夹结构被破坏：**解压实例过程时产生了“文件夹”（多了一层），或者随便移动了`Core`、`Drivers`等文件夹的位置，导致相对路径（`../`）失效。
    
4. **路径包含中文或空格：**例如放在`D:\桌面\单片机 代码\`下，Keil极容易解析失败。
    

---

## 三、终极解决步骤（按顺序操作）

### 第一句话：删除存储器（杀手锏）

当连系统自带库（如`stddef.h`）都找不到时，用此招可以即时解决。

1. **彻底关闭**当前报错的Keil软件。
    
2. 进入工程文件（`.uvprojx`）所在的电脑文件夹。
    
3. 找到同名但后缀为**`.uvoptx`**的文件（例如`TEST.uvoptx`）。 _(注：如果`.uvguix.xxx`有的文件也可以并删除，它们都是界面排版和路径的存储文件)_
    
4. **直接删除**该文件。
    
5. 重新打开绿色的`.uvprojx`工程文件Keil。
    

### 第二招：重置包含路径(Include Paths)

如果删除了存储仍然缺少特定的头文件（如`lcd.h`）：

1. 点击Keil顶部的**魔术棒(Options for Target)** -> 选择**C/C++**选项卡。
    
2. 点击右侧的**包含路径**`...`按钮。
    
3. **明确所有绝对路径**（绝对不能有类似的`D:\STM32\ARM\...`绝对定位的路径）。
    
4. **添加正确的相对路径**：点击新建，手动浏览并添加头文件所在的目录（如`..\Core\Inc`，`..\HARDWARE`等）。
    

### 第三招：重新关联源文件（针对.c文件爆黄）

如果是具体的`.c`源文件爆黄，说明物理文件被移动了：

1. 在带感叹号的`.c`文件上右键 -> 选择**删除文件**。
    
2. 在对应的组（Group）文件夹上右键 -> 选择**Add Existing Files to Group...**。
    
3. 进入电脑文件夹里，手动把那个`.c`文件重新添加进来。
    

### 第四招：终极重启

完成上述操作后，**必须点击Rebuild（两个箭头的图标）**进行全工程重新编译，让Keil重新扫描所有路径。

---

## 四、避坑最佳实践（以后如何避免）

1. **解压即用：**厂家的实例程压缩包，解压到一个文件夹后，**千万不要去乱动里面的子文件夹结构**。
    
2. **绝对英文路径：**养成良好习惯，所有的工程都放在如`D:\STM32_Code\Project_Name`这样**全英文、无空格、且体系较浅**的目录下。
    
3. **不要轻易改编译器版本：**老例程就用默认的`Use default compiler version 5`，强行改成版本6会导致几个不兼容的语法错误。
