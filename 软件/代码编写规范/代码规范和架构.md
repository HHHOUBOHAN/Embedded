# 代码架构
1. BSP层
	- MCU与外设期间的交互过程
	- 分两种情况：裸机，操作系统
2. core
	- 面向mcu进行编程 ，初始化MCU内部的外设，包含mian文件
3. Drivers(厂商SDK程序)
	- MCU厂商和MCU内的CPU厂商提供的，用来对CPU和偏上外设编程时用的驱动库，一般由厂家提供
4. Middlewares: 中间件
	- 抽象程度很高，能在各个项目中安插通用的：LVGL\FreeRTOS\数学库\快速傅里叶变换库
5. SYSTEM:系统配置层
	- 对系统定义整体的宏
6. 应用层
	- 实现具体的应用逻辑
# 代码规范
## 头文件包含
(1) 先系统文件，后用户头文件. 系统文件使用: `#include <xxx.h>`，
自定义和第三方库头文件使用: `#include "xxx.h"`
(2) 如果头文件与程序文件在同一个子目录里，则可以这么写: `#include "./xxx.h"`
(3) 如果头文件在上级子目录,则可以这么写: `#include"../xxx.h"`
(4) 如果头文件位于某个下级子目录里,那么以下级子目录的名字开头: `#include"somedir/xxx.h"`
(5) 如果头文件位于某个与当前子目录平行的"兄弟"子目录里，则需要这么写: `#include"../somedir/xxx.h"`
(6) 只引用需要的头文件
## C文件常规规则
(1) 文件名常用大小写混合，或者小写混合. 例如DiyMainview.c infoview.c（骆驼）
(2) C文件中的内容顺序: 所包含的头文件，宏定义，全局变量，函数定义.
