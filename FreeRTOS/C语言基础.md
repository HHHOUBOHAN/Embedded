# 3.2 变量在SRAM里的分布
## 3.2.1 单片机的FLASH和SRAM
1. 内存和硬盘：如果数据存储在内存里，那么断电之后就消失了；而如果存储在硬盘里咋，即使断电后数据也能保存下来![[Pasted image 20261004174554.png]]
2. 单片机和电脑非常像，Flash就相当于电脑上的硬盘，SRAM就相当于电脑上的内存![[Pasted image 20261004174714.png]]
	- cotex-M3是单片机的内核，内核负责运算，就像电脑的CPU
	- 总线矩阵相当于电脑的主板
	- Flash相当于硬盘，程序和常量存储在这里
	- SRAM相当于内存，变量存储在这里
3. FLASH里:程序当中需要长期存储的、不可变的部分                 
4. SRAM里:临时存储的、经常变化的部分

|阶段|住哪|特点|
|---|---|---|
|编译/烧录时|**FLASH**（仓库）|掉电不丢。代码、常量、`.data` 的**初始值**都存在这|
|上电启动时|启动代码干活|把 `.data` 从 FLASH **拷贝**到 SRAM；把 `.bss` **清零**；设好栈指针|
|运行时|**SRAM**（工作台）|掉电就没了。变量、堆、栈都在这|

# 3.4 栈
## 3.4.1 数据结构“栈”
1. 栈是一种“后进先出”的数据结构
2. 相关概念：栈顶，栈底，栈深度，压栈，弹栈，后进先出（最后放进去的东西最先拿出来）![[Pasted image 20261006125715.png]]
## 3.4.2 调用栈
1. SRAM分成了四个段：.data段  .bss段 .heap段 .stack段 （用来储存调用栈）![[Pasted image 20261006130204.png]]
2. “调用栈” 就是由系统自动维护的栈，它的作用是在函数调用发生的时候保存上下文![[Pasted image 20261006130443.png]]
	- **函数调用之前需要保存上下文**（子函数执行之后返回回去的所需要的必要的信息），包括：参数，局部变量和返回地址
	- 上述例子就是逐层进行函数计算，当最外层的函数要跳到内层函数去执行的时候需要保存外层函数参数，局部变量和返回地址，并且压入栈中，如此重复，执行到最内层函数后，最内层函数会返回结果给上一层，这个时候就会将上一层函数的上下文弹出栈，然后重复上述操作，而实现这个操作就需要栈这个数据结构，即先进后出 
	- 函数调用是最后调用的最先返回 栈是后进先出  
	- 在多层嵌套的函数调用中（如 `main -> f -> g -> square`），底层系统正是利用**栈（Stack）**这种数据结构实现了逐层计算与返回。当外层函数调用内层函数时，CPU硬件会自动将返回地址压入栈，参数通常优先通过寄存器传递（过多则压栈）；进入内层函数后，内层函数会开辟自己的栈帧（Stack Frame），保存外层函数的寄存器上下文（保护现场），并为自己的局部变量分配空间，如此逐层嵌套压栈。当执行到最内层函数计算完毕后，它会将结果存入约定的寄存器（如R0），然后清理自己的栈帧（出栈），此时上一层函数的上下文暴露出来，上一层恢复现场继续执行，以此类推逐层返回。整个过程完美契合了栈**“先进后出（LIFO - Last In First Out）”**的特性：最先被压入的主调函数（`main`）上下文最后才被弹出，最后被压入的最内层函数（`square`）最先被弹出。在FreeRTOS中，**每个任务都拥有独立的栈空间**，任务切换的核心正是内核替当前任务将CPU寄存器等上下文压入其私有栈，再从另一个任务的私有栈中弹回上下文，从而实现多任务的无缝并发执行。
