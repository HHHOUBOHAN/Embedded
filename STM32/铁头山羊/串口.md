# 1.1 通信协议
1. 串口引脚                                                                                                                            ![image-1793967340149.png](attachments/image-1793967340149.png)
	- Tx: Transmit 数据发送引脚
	- Rx：Receive 数据接收引脚
2. 串口数据帧格式：高电压（空闲），第一个下降沿是起始位，高电平表示1，低电平表示0，每次传输一个字节，然后发送方会发动一个高电压（停止位），如此循环往复![image-1793967631009.png](attachments/image-1793967631009.png)
3. 示例：
	- 通过串口发送十进制 数字27: 二进制为00011011
	- 发送字符串“Hello”   ASCII码 H=0x48, e=0x65, l=0x6c, o=0x6f
	- 串口通信默认是从低位开始发送（从右往左传）![image-1793968110798.png](attachments/image-1793968110798.png)
4. 数据帧格式设置
	 - 数据位长度：八位或九位
	 - 校验位使能和禁止，数据位的最后一位作为校验位
	 - 停止位的长度：0.5，1，1.5，
	 - ![image-1793968221526.png](attachments/image-1793968221526.png)
	 - 数据位和校验位的组合，常用第一个格式和第四个格式![image-1793968664250.png](attachments/image-1793968664250.png)
	 - 校验方式：
		 - 奇校验：要求数据位中有奇数个1
		 - 偶校验：要求数据位中有偶数个1
		 - ![image-1793968772660.png](attachments/image-1793968772660.png)
		 - 示例：
			 - 奇校验：发送方发送85（0101 0101），前面总共有八个比特有四个1，但是是奇校验，所以校验位要写1，从而符合奇数个1
			 - 接收方会检验是奇数个1还是偶数个1，从而实现校验功能

## 1.3.4 IO配置表
1. 配置表 ![image-1794024182241.png](attachments/image-1794024182241.png)
	- 全双工：数据可以**同时**双向传输（发送和接收双方分别拥有一条线）
	- 全双工同步模式：在全双工的基础上，使用同步时钟信号
	- 半双工：数据可以双向传输，但同一时刻只能有一个方向传输（发送和接收双方共用一条线）
	- 半双工同步模式：使用时钟信号协调传输
	- USARTx_CK(同步模式)：使用额外的时钟信号协调数据传输
	- USARTx_RTS（硬件流量控制）：由本设备发出，用来告诉对方自己当前是否还能接收数据，如果接收缓冲区快满了，就通知对方暂停发送；
	- USARTx_CTS（硬件流量控制）：由对方发出，用来告诉本设备是否可以继续发送数据，如果对方暂时无法接收，就通知本设备暂停发送。
	- RX全双工模式最好是选用输入上拉，因为当发送数据结束后，高电平表示空闲，输入上拉正好提供了这个高电平

# 1.4 发送数据
## 1.4.1 回顾串口数据发送过程
1. 内部结构框图：CPU写入发送字节寄存器中，![image-1794107104617.png](attachments/image-1794107104617.png)
## 1.4.2 TxE标志位
1. TXE：Transmit Data Register Empty 发送数据寄存器空，当TDR空时，TxE=1；否则TxE=0![image-1794107425302.png](attachments/image-1794107425302.png)
2. 数据写入发送数据寄存器之前，要判断发送数据寄存器是否为空，这个时候就需要 TXE来判断
## 1.4.3 TC标志位
1. TC：Transmit Complete - 发送完成，当TDR空且移位寄存器空时候，TC=1；否则TC=0![image-1794107635387.png](attachments/image-1794107635387.png)
2. 发送数据寄存器（待发送），移位数据寄存器（发送中），只有两个寄存器都为空，才能判定发送结束
3. 发送流程：首先由 CPU 将需要发送的数据写入发送数据寄存器，随后数据被转移到发送移位寄存器，由移位寄存器将原本并行的 8 位数据转换成串行数据，按照低位先发的顺序，逐位从 Tx 引脚发送出去。整个过程中，波特率发生器根据时钟和波特率寄存器（BRR）的配置，控制每一位数据的发送时间。发送完成后，通过 TXE 和 TC 标志位判断发送状态：TXE 表示发送数据寄存器为空，可以继续写入数据；TC 表示整个数据已经发送完毕。
## 1.4.4 编程接口
1. `USART_Cmd`
	- 控制USART模块的使能和禁止（总开关）
	- 参数：串口名称，是否使能
	- 结构框图![image-1794107825550.png](attachments/image-1794107825550.png)
2. `USART_GetFlagStatus`
	 - 作用：查询USART标志位的值。返回值：RESET - 0 , SET - 1;
	 - 参数：串口名称，要查询标志位
	 - 标志位：USART_FLAG_TXE,USART_FLAG_TC,USART_FLAG_PE,USART_FLAG_RXNE![image-1794108657035.png](attachments/image-1794108657035.png)
3. `USART_SendData`
	- 作用：把要发送的数据写入到发送数据寄存器里
	- 参数：串口名称，要发送数据
	- 一般以一个字节发送一个数据, 之所以用uint16_t(无符号标志位)，因为当串口数据位为九位的时候，用uint8_t就不能发送出去![image-1794108856561.png](attachments/image-1794108856561.png)
## 1.4.5 编写代码
1. 自定义串口发送函数![image-1794109222850.png](attachments/image-1794109222850.png)
```c
void My_USART_SendBytes(USART_TypeDef *USARTx, uint8_t *pData, uint16_t Size);  //要发送的数据pData   Size 发送字节数

void My_USART_SendBytes(USART_TypeDef *USARTx, uint8_t *pData, uint16_t Size)
{
	for(uint32_t i=0; i < Size; i++)
	{
		//先判空
		while(USART_GetFlagStatus(USART1,USART_FLAG_TXE) == RESET);
		USART_SendData(USART1,pData[i]);
	}
	while(USART_GetFlagStatus(USART1,USART_FLAG_TC) == RESET);
}
uint8_t bytesToSend[] = {0,1,2,3,4,5};
	
	My_USART_SendBytes(USART1,bytesToSend,6);
```

# 1.6 接收数据
## 1.6.1 回顾接收数据的过程
1. 接收数据过程：外部串行信号从**Rx引脚**进入，时钟经过**波特率寄存器（BRR）**分频后提供精准的采样节拍，**控制电路**根据配置好的数据帧格式（数据位、停止位、校验位）识别起始位后，在时钟节拍下将外部电平一位一位地推入**接收移位寄存器**（完成串转并）；当攒满一个字节后，数据被整体移入**接收数据寄存器**，此时硬件会自动置位 **RxNE（接收非空）** 标志位（若发生校验错、帧错等也会置位PE、FE等错误标志），CPU只需通过轮询该标志位或响应中断，就能把数据从寄存器中读走![image-1794121796374.png](attachments/image-1794121796374.png)
## 1.6.2 RxNE标志位
1. RxNE: Receive Data Register Not Empty - 接收数据寄存器非空,  当RDR非空时，RxNE=1;否则 RxNE=0![image-1794122215019.png](attachments/image-1794122215019.png)

## 1.6.5 错误标志位
1. PE: Parity Error - 奇偶校验错，如果接收到的数据有校验错误，PE=1,否则 PE=0![image-1794126937566.png](attachments/image-1794126937566.png)
2. FE: Frame Error - 帧格式错误，接收到无效的数据帧，则FE=1;否则FE=0![image-1794127021362.png](attachments/image-1794127021362.png)
3. NE：Noise Error - 噪声错 接收的数据中检测到了噪声，则NE=1；否则NE=0   
	1. 噪声错：接收方对每一个位会进行多次采样，只有多次采样相同的时候才会确定此位为对应电平，但是如果多次采样结果不一致的时候，这个时候就是噪声错![image-1794127133471.png](attachments/image-1794127133471.png)
4. ORE：Overrun Error - 过载错，由于过载造成了数据丢失，则ORE=1 ；否则ORE=0
	1. 过载错：发送的某一个字节在接收数据寄存器不移动，后面的字节会进入移位寄存器中，但是后序会有大量字符串进入这个移位寄存器中，这个时候就会把之前在移位寄存器中的值进行覆盖，这个就是过载错![image-1794127363422.png](attachments/image-1794127363422.png)
