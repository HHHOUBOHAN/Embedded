# 1. 串口的缺点
1. 传输速度相对慢
	- 串口是一位一位传的，相比并口、USB、以太网这种高速通信，速度比较低
	- 常见波特率为：`9600  115200  921600`虽然能用，但传大量数据时比较慢
2. 一次只能点对点通信
	- 普通UART一般是两个设备之间通信
		- 设备A_TX ---- 设备B_RX
		- 设备A_RX ---- 设备B_TX
		- GND     ---- GND
	- 如果多个设备同时挂一条线上，就容易冲突,不像 I2C 那样天然支持多个从机地址
3. 没有地址机制
	- 串口本身只负责收发数据，不知道：这个数据发给谁 ，这个数据从谁来
	- 如果多个设备通信，需要自己设计协议: 帧头 + 设备地址 + 数据 + 校验 + 帧尾
4. 发送和接收双方波特率必须一致
	-  如果STM32设置和串口设置不同就会出现：乱码  收不到数据  数据错误
5. 抗干扰能力一般
	- 普通 TTL 串口电平是：`0V / 3.3V`
	- 距离远了容易受干扰,所以普通 UART 适合短距离通信
	- 如果距离远，转成 RS232  RS485  CAN
6. 没有时钟线，依赖双方时钟精度
	- UART 是异步通信，没有专门的时钟线。
	- 双方靠约定好的波特率来同步。
	- 如果时钟误差太大，就可能采样错误，导致乱码。

5. 从机都有一个7位的地址  从`0000000`到`1111111` ,可以理解为0到127，故总共又128个地址 ，最多可以和128个从机通信
6. 通信流程：主机发送从机地址，与从机建立通信
# 3. 数据线和时钟线
 1. 时钟线传输时钟 数据线传输数据
 2. 时钟信号总是从主机发送从机，数据信号通信方向是双向的
 3. 时钟信号每一个周期，数据信号会传输一个数据，所以时钟信号的频率(周期)决定了数据传输的快慢
# 4. 逻辑线与
1. 数据线和时钟线有上拉电阻
2. 从机和主机的所有的SCL和SDA引脚都设置为开漏输出（单片机通过驱动一个MOS管来驱动IO引脚的输出高低电压的，开漏模式即上面MOS管断开，只控制下面的MOS管，写0的时候下面MOS闭合，输出的是低电压，写1的时候下面的MOS管断开，输出的是高阻抗）

4. 硬件电路是如何实现逻辑与运算的![[Pasted image 20260903174805.png]]
	-  把所有的SCL都设置为开漏输出模式
	-  如果所有的SCL引脚都写1的话，输出的高阻抗，相当于引脚从电路上断开了，中间这条线就悬空了，但是有上拉电阻。上拉电阻会把悬空的时钟线拉到高电压
	-  如果向其中一个引脚写0的话，写1的引脚输出的高阻抗，相当于引脚从电路上断开了。而写0的引脚输出的低电压，就相当于通过写0的引脚从而实现接地，导致上拉电阻就不起作用，因此得出输出的是低电压，所以只要有一个引脚写0就能导致上拉电阻失效，从而输出低电压
# 5. 主机如何发送时钟信号
1. 时钟方向是单向的（只能由主机发送给从机）
2. 产生方波信号：所有从机输出1，且同时为开漏输出，从而达到高阻抗，相当于断开；然后控制主机的SCL引脚，从而交替的写0和1，当写0开漏模式输出低电压的时候这个SCL就相当于接地，当写1的时候，开漏模式导致高阻抗，时钟线悬空，上拉电阻会把悬空时钟线拉到高电压

# 6. 主机如何发送数据
1. 让所有从机的SDA引脚写1，然后控制主机的SDA，向SDA引脚中写0/1，写0的时候开漏模式输出低电压，写1的时候开漏模式输出为高阻抗，但是有上拉电阻，从而实现输出高电压
