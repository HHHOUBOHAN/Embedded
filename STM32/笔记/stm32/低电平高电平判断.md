#  Signal
## Signal 的两种典型状态

### 1. 显示具体信号名（如 SPI1_SCK、USART1_TX）

当 Signal 显示为具体名称时，表示该引脚**被分配给了某个外设模块**。

**常见示例：**

|引脚|Signal|含义|
|---|---|---|
|PA5|SPI1_SCK|PA5 作为 SPI1 的时钟信号|
|PA9|USART1_TX|PA9 作为 USART1 的发送引脚|
|PB6|I2C1_SCL|PB6 作为 I2C1 的时钟线|
|PA1|ADC1_IN1|PA1 作为 ADC1 的模拟输入通道1|

**特点：**

- 引脚功能由外设硬件自动控制
    
- 用户代码通过操作外设寄存器来间接控制引脚行为
    
- 例如配置为 SPI_SCK 后，启动 SPI 传输时，硬件自动产生时钟信号
    

---

### 2. 显示 n/a（not applicable）

当 Signal 显示 **n/a** 时，表示该引脚**没有分配给任何外设**，处于"未分配"状态。

**这时通常配合 GPIO Mode 使用：**

- **GPIO Mode = Output**：作为普通输出引脚
    
- **GPIO Mode = Input**：作为普通输入引脚
    
- **GPIO Mode = Analog**：作为模拟引脚（如 ADC 输入，但需要单独配置外设）
    

**特点：**

- 引脚完全由用户代码通过 GPIO 寄存器直接控制
    
- 没有硬件外设接管该引脚
    
- 灵活性最高，适合控制 LED、读取按键、驱动简单外设等
    

---

## 三、为什么 Signal 显示 n/a 却还能工作？

很多初学者会有疑问："为什么 n/a 还能输出高低电平？"

**原因：**

- n/a 只是表示"没有外设功能分配"
    
- 但 GPIO 本身（通用输入输出）始终是可用的
    
- 在 CubeMX 中，你可以独立配置 GPIO Mode 为 Output 或 Input
    
- 这两个配置是**正交的**：
    
    - Signal = n/a + GPIO Mode = Output → 普通输出
        
    - Signal = SPI1_SCK + GPIO Mode = Alternate Function → 外设功能

## 五、实际代码生成的差异

### 情况1：Signal = n/a，GPIO Mode = Output

生成的代码（HAL 库风格）：

c

// 初始化 GPIO 引脚
GPIO_InitStruct.Pin = GPIO_PIN_5;
GPIO_InitStruct.Mode = GPIO_MODE_OUTPUT_PP;  // 推挽输出
GPIO_InitStruct.Pull = GPIO_NOPULL;
GPIO_InitStruct.Speed = GPIO_SPEED_FREQ_LOW;
HAL_GPIO_Init(GPIOA, &GPIO_InitStruct);
// 用户直接操作
HAL_GPIO_WritePin(GPIOA, GPIO_PIN_5, GPIO_PIN_SET);  // 输出高
HAL_GPIO_WritePin(GPIOA, GPIO_PIN_5, GPIO_PIN_RESET);// 输出低

### 情况2：Signal = SPI1_SCK，GPIO Mode = Alternate Function

生成的代码：

c

// 初始化 GPIO 为复用功能
GPIO_InitStruct.Pin = GPIO_PIN_5;
GPIO_InitStruct.Mode = GPIO_MODE_AF_PP;  // 复用推挽
GPIO_InitStruct.Pull = GPIO_NOPULL;
GPIO_InitStruct.Speed = GPIO_SPEED_FREQ_HIGH;
GPIO_InitStruct.Alternate = GPIO_AF5_SPI1;  // 指定复用功能编号
HAL_GPIO_Init(GPIOA, &GPIO_InitStruct);
// 还需要初始化 SPI 外设
// 引脚电平由 SPI 硬件自动控制，用户不能直接通过 GPIO 函数控制

## 六、总结

|项目|Signal = n/a|Signal = 具体外设名|
|---|---|---|
|**含义**|未分配外设功能|分配给某个外设|
|**GPIO Mode**|Input/Output/Analog|Alternate Function|
|**控制方式**|用户通过 GPIO 寄存器直接控制|外设硬件自动控制|
|**适用场景**|LED、按键、简单 IO|SPI、I2C、USART、PWM 等通信/定时功能|
|**代码操作**|`HAL_GPIO_WritePin` 等|通过外设句柄操作（如 `HAL_SPI_Transmit`）|

**一句话总结：**

> Signal 显示 n/a 意味着这个引脚现在是"自由身"，完全由你的代码通过 GPIO 函数直接控制；如果显示了具体信号名，说明它已经被某个外设"征用"，需要通过该外设的 API 来间接控制其行为。
 
# GPIO Mode
## 📝 STM32 GPIO 核心知识点总结

### 一、GPIO的四种基本模式（Mode）

引脚就像一个多面手，根据你的配置扮演不同的角色：

|**模式**|**信号方向**|**关键特征**|**典型应用场景**|
|---|---|---|---|
|**输入（输入）**|外部$\rightarrow$MCU|图像电压表，读取电平|**按键**、开关传感器、高低电平检测|
|**输出（输出）**|MCU$\rightarrow$外部|如电源/地线，控制水平|**LED亮灭**、蜂鸣器、继电器控制|
|**复用 (AF)**|外设$\leftrightarrow$外部|迁移硬件模块控制|**串口通信 (UART)**、电机调速 ( **PWM** )|
|**模拟（模拟）**|外部$\rightarrow$ADC|不处理0/1，处理连续电压|**测量电压**、光敏电阻读取、**最省电**|

---

### 二、输出模式的两种绝招（Output Type）

当你选择了“输出”模式时，你还决定怎么输出：

- **推挽输出（Push-Pull）**：
    
    - **原理**：内部两个开关（PMOS/NMOS）轮流转，能推电流也能拉电流。
        
    - **特点**：速度快、驱动力强。**控制LED的首选。**
        
- **开漏输出（Open-Drain）**：
    
    - **原理**：只能往里吸电流（输出0），不能往外推（输出1时呈高阻态）。
        
    - **特点**：需要接外部上拉电阻。常用于**I2C接入**或多个设备连接同一条线。
        

---

### 三、内部上下拉电阻（Pull-up / Pull-down）

为了防止引脚在没人管的时候“发疯”（电平乱跳），需要给我们一个根本线索：

- **上拉 (Pull-up)**：无信号时，引脚被内部电阻拉到**3.3V (高)**。
    
- **下拉 (Pull-down)**：无信号时，引脚被内部电阻拉到**0V (低)**。
    
- **浮空 (None)**：不接电阻。**输出模式**通常选这个；输入模式下外部除非有电路，否则慎用。
    

---

### 四、核心HAL库函数

写代码时，你最常用的“三剑客”：

1. **写入状态**：`HAL_GPIO_WritePin(PORT, PIN, GPIO_PIN_SET/RESET);`
    
2. **读取状态**：`if(HAL_GPIO_ReadPin(PORT, PIN) == GPIO_PIN_RESET) { ... }`
    
3. **翻转状态**：`HAL_GPIO_TogglePin(PORT, PIN);`（切换亮灭最快的方法）
    

---

### 五、实战小贴士（温馨提示）

- **消（Debounce）**：机械按键按下时会有5-20ms的物理衰减，代码抖里必须加`HAL_Delay(20)`确认。
    
- **低电平点亮**：如果你的LED灯接了3.3V，那么代码里写`RESET`(0)才开灯。
    
- **用户标签**：在CubeMX里给引脚起个名字（比如`LED`），代码里`LED_Pin`会比`GPIO_PIN_5`专业旋转。
