# UART收发数据

本文讲解了如何使用STM32CubeMx配置STM32F407的串口，实现与电脑上位机的通讯，并控制LED。

## 一.准备工作

### 硬件准备

- `STM32开发板`
- `串口`

开发板集成了USB转TTL，使用USB-UART的USB接口就可以直接使用串口了

相关原理图如下：

![](https://www.minnatec.com/prod-api/profile/upload/2025/12/30/4044ebadbc9c4c8ea8a01b7dc67ace3e.png)

使用CH340N芯片将USB数据转换为串口数据，串口使用的引脚是PC10,PC11（USART3或UART4）。

### 软件准备

- 完成`STM32CubeMx`安装
- 参考`Keil` 编辑器`MDK`开发环境配置

## 二.生成MDK工程

### 1.配置UART

![](https://www.minnatec.com/prod-api/profile/upload/2025/12/30/5dd17c03faa54d03baeebb4d76ec6298.png)

1.点击引脚，选择USART3_TX和USART3_RX

2.在左侧标签栏选择USART3

3.Mode选择Asynchronous（全双工异步通信）

4.中断使能

  

![](https://www.minnatec.com/prod-api/profile/upload/2025/12/30/e171539bbdac493399c0cce5cd7a51e6.png)

进入Parameter Settings，此界面可以配置串口通信参数

波特率：每秒钟可以传输的码元数量，可以简单理解为通信速率，数值越高，速度越快。

数据位：每帧数据的实际位数，一般使用8位，也就是一个字节

校验位：数据发送后对数据进行校验

停止位：代表该数据包传输完成

通信双方的四个参数必须保持一致，才能保持正常的通信。当前配置下这四个参数直接默认即可。

配置PA5为GPIO_Output用来控制LED，其他保持默认即可，GPIO_Output默认为推挽输出。

## 三.编译测试

### 1.串口收发函数

```c
HAL_StatusTypeDef HAL_UART_Transmit(UART_HandleTypeDef *huart, const uint8_t *pData, uint16_t Size, uint32_t Timeout);
HAL_StatusTypeDef HAL_UART_Receive(UART_HandleTypeDef *huart, uint8_t *pData, uint16_t Size, uint32_t Timeout);
HAL_StatusTypeDef HAL_UART_Transmit_IT(UART_HandleTypeDef *huart, const uint8_t *pData, uint16_t Size);
HAL_StatusTypeDef HAL_UART_Receive_IT(UART_HandleTypeDef *huart, uint8_t *pData, uint16_t Size);
```

**参数：**

*huart：HAL库给串口定义的名称，选择对应的串口号即可。

*pData：发送或接收的数据地址

Size：发送或接收的数据长度

Timeout：阻塞式函数的超时时间。

**函数：**

`HAL_UART_Transmit()`：阻塞发送，装载好数据后，程序会一直进行发送，直到发送完毕或超时退出。

`HAL_UART_Receive()`： 阻塞接收，程序会一直等待接收，直到接收到指定的数据长度或超时退出

`HAL_UART_Transmit_IT()`：中断发送，函数启动后会直接返回，然后在中断里进行自动发送。发送够指定长度后，会进入回调函数，用户可在回调函数里执行操作。

`HAL_UART_Receive_IT()`：中断接收，函数启动后会直接返回，然后在中断里进行自动接收。接收够指定长度后，会进入回调函数，用户可在回调函数里执行操作。

### 2.串口中断回调函数

串口中断发送、串口中断接收函数完成任务后，会进入串口中断回调函数，串口中断函数需要用户重新编写。

`HAL_UART_TxCpltCallback(UART_HandleTypeDef *huart)` 串口发送中断回调函数

`HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)` 串口接收中断回调函数

### 3.编写定长接收代码

```c
void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
    if (huart->Instance == USART3)
	{
	  if(Rxdata=='0')
	   {
		  HAL_GPIO_WritePin(GPIOA, GPIO_PIN_5, GPIO_PIN_RESET);
		  HAL_UART_Transmit(&huart3,"执行完成",sizeof("执行完成"),0xff);  //串口打印数据
	   }
	  else if(Rxdata=='1')
	   {
		  HAL_GPIO_WritePin(GPIOA, GPIO_PIN_5, GPIO_PIN_SET);
		  HAL_UART_Transmit(&huart3,"执行完成",sizeof("执行完成"),0xff);  //串口打印数据
	   }
      else
	   {
		  HAL_UART_Transmit(&huart3,"执行失败",sizeof("执行失败"),0xff);  //串口打印数据
	   }
	  HAL_UART_Receive_IT(&huart3,&Rxdata,1);    //重新开启中断接收
	 }
}
```

将串口中断回调函数添加到main.c函数的 USER CODE BEGIN--USER CODE END中间。

进入函数首先判断是哪个串口中断被触发，然后执行对应代码。

中断回调函数中慎用HAL_Delay()函数，可能会造成程序阻塞卡死，可以通过将外部中断优先级调低解决问题。

中断函数中尽量不要做处理时间较长的操作，会影响其他代码的响应时间，建议中断函数仅处理标志位，循环到While(1)中处理。

执行完操作后，需要再次调用中断接收函数，这样下次有数据来时，才能再次进入中断回调函数。

### 5.不定长数据接收

由于大部分协议的长度是不固定的，例如WiFi的AT指令，都是不定长的字符串。事先不知道报文的长度，我们应该怎么去接收呢？

HAL库提供了一个非常方便的函数：空闲中断函数

空闲中断触发方式：当一段数据包传输完毕后，串口总线会处于空闲状态，硬件检测到总线空闲时，程序会自动进入到中断回调函数中。此时我们接收到的数据不会局限于固定的长度，而是一段不定长的数据包。

```c
HAL_StatusTypeDef HAL_UARTEx_ReceiveToIdle(UART_HandleTypeDef *huart, uint8_t *pData, uint16_t Size, uint16_t *RxLen,
                                           uint32_t Timeout);
HAL_StatusTypeDef HAL_UARTEx_ReceiveToIdle_IT(UART_HandleTypeDef *huart, uint8_t *pData, uint16_t Size);
```

这两个函数分别是阻塞式空闲接收，中断式空闲接收。接收建议使用中断接收，不会阻塞其他代码的运行。

### 6.编写不定长接收代码

空闲中断回调函数为`HAL_UARTEx_RxEventCallback(UART_HandleTypeDef *huart, uint16_t Size)`，需要重写空闲中断函数来执行用户操作。

空闲中断回调函数的参数中，多出一个Size。这个参数是空闲接收时，收到的数据的长度。比如接收到一个"HELLO"，那么Size就是5。


### 7.串口重定向printf()函数

C语言中的printf()函数是非常方便的打印函数，在STM32中也可以使用printf()来代替串口发送函数。

**具体实现方式如下：**

```c
#include "stdio.h"
int fputc(int ch, FILE *f)
{
 
  HAL_UART_Transmit(&huart3, (uint8_t *)&ch, 1, 0xFFFF);
  return ch;
 
}
```

需要先引用C语言函数库<stdio.h>，再将fputc里面的输出指向串口，我们使用的是串口3，将usart3发送函数填写进去即可。

**编写测试函数**

```c
uint8_t Txdata='1';
	printf("\r\n");
	printf("%c\r\n",Txdata);
	printf("%x\r\n",Txdata);
	printf("%d\r\n",Txdata);
```
